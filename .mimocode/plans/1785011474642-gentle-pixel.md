# Naprawa obrotu jednostek podczas chodzenia

## Problem

Jednostki na ekranie bitwy "kręcą się" (sprite kierunku przełącza się szybko lewo/prawo/góra/dół). Główna przyczyna: funnel algorithm generuje zigzag waypoints w wąskich przejściach, a `GetNextWaypoint` z progiem 6px błyskawicznie przez nie przechodzi.

## Analiza przyczyn (5 mechanizmów)

### Mechanizm B (główny): Funnel zigzag waypoints
Funnel w wąskich przejściach generuje bliskie siebie waypoints o naprzemiennym kierunku X:
```
WP N:   (100, 200) → jedzie w prawo
WP N+1: (105, 198) → jedzie w prawo+góra
WP N+2: (100, 196) → jedzie w LEWO+góra  ← zmiana kierunku!
WP N+3: (105, 194) → jedzie w prawo+góra
```
Próg 6px powoduje że jednostka przeskakuje przez te waypoints w 1-2 tickach.

### Mechanizm A: Oś Y zawsze nadpisuje oś X
W `A_RUCH` sprawdzenie X i Y jest sekwencyjne - BNR z ruchu w lewo/prawo jest nadpisywany przez BNR z ruchu góra/dół. Przy ruchu diagonalnym sprite zawsze pokazuje tylko pionowy kierunek.

### Mechanizm C: Agresywny próg arrival (6px)
`GetNextWaypoint` przeskakuje do następnego waypointa gdy |delta| <= 6 w obu osiach. To za mało - jednostka w 1 ticku (SPEED=5px) może przeskoczyć przez 2-3 waypoints.

### Mechanizm D: Sidestep reset
Sidestep resetuje kierunek co tick gdy jednostka jest odblokowywana i ponownie blokowana.

## Plan naprawy

### Fix 1: Post-funnel zigzag cleanup (Pathfinder.cs)

Po funnel algorithm, przefiltruj waypoints które powodują zigzag:
- Jeśli 3 kolejne waypoints mają naprzemienne znaki WROZX (±) przy małej zmianie Y, usuń środek
- Minimalny odległość między waypoints: 12px (1.5 komórki)

```csharp
// W FunnelSimplify, przed return:
waypoints = RemoveZigzag(waypoints, minDistance: 12);
```

### Fix 2: Fix sprite direction priority (LegionMainAction.cs)

Zmień logikę BNR w A_RUCH: wybieraj oś z **większą** odległością do waypointa, zamiast zawsze nadpisywać Y przez X.

Zamiast:
```
if (|WROZX| > 4) { BNR = left/right }
if (|WROZY| > 4) { BNR = up/down }  // zawsze nadpisuje
```

Użyj:
```
if (|WROZX| > 4 && |WROZX| >= |WROZY|) { BNR = left/right }
else if (|WROZY| > 4) { BNR = up/down }
```

### Fix 3: Zwiększ próg arrival (LegionMainAction.cs)

Zmień `WaypointArriveDistance` z 6 na 10:
```csharp
private const int WaypointArriveDistance = 10;
```

To daje jednostce więcej czasu "stabilnego" kierunku między zmianami waypoints.
